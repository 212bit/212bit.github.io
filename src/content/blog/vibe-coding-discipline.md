> 读帖笔记。原帖：[【vibe coding教程】如何正确的开始vibe coding](https://linux.do/t/topic/2993279)（LINUX DO，作者 gpt1，2026-10-08，373 reactions / 3.7k 浏览）。原帖的观点，拆解和不同意见属于我。

收藏夹里的热帖很多，真按它做完一遍的很少。这篇值得认真读一次的原因很简单：它讲的不是「怎么写 prompt」，而是**把传统软件工程压缩成单人 + Agent 的工作流**。以下按我的拆法重组，不逐段复述。

## 一、四步法

**第 0 步，从 ChatGPT 模式切到 Agent 模式。** 热帖开头专门强调这一条，很多人卡在这里：还在用一问一答的方式用 Agent，自然体会不到工作流的差别。

**第一步，不要反复造轮子。** 动手前先让 Agent 去 GitHub 深搜同类项目，用 star 数和维护活跃度判断参考价值。成熟项目直接用，连 vibe coding 都省了。

**第二步，讨论先行，分歧清零。** 全帖被引用最多的是这句提示词：

> 如果你还有任何问题或建议可以先向我提出，解决所有分歧和阻塞后再执行任务。

放在任务结尾或全局指令里。它解决的是 Agent 开发特有的痛点：模型不会像人类同事那样在开工前开需求会，它要么中途反复停下来问，要么带着错误假设一路狂奔。把「先问清所有分歧」变成显式指令，等于把需求评审内置进了流程。

**第三步，工程文件即持久化记忆。** 因为开发不可能只用一个对话、一个模型、甚至一个平台，热帖要求开工前建好一批固定文件：`PROJECT_INDEX.md` 管定位与路由，`NOW.md` 管当前进度，`MAP.md` 管路径映射，`RUNBOOK.md` 管构建运行，`DECISIONS.md` 与 `RISKS.md` 沉淀决策和风险，再加一个项目入口的 agent md，教接手的模型**怎么按需检索**这些文件。其中最关键的一条规则：模型必须搜索定位，禁止默认读全文件——否则 token 先爆，判断力跟着爆。

**第四步，旗舰策划，性价比执行，独立窗口审查。** 最强模型做方案，方案对话只审查不开发；执行交给便宜模型，一个对话最多干一个半小时，上下文压缩超过五次就换新对话；审查交给另一个窗口的另一个模型，摆脱长上下文的惯性。作者还演示了一个漂亮的自我改进闭环：让便宜模型把历史 UI 任务按「是否返工」打分攒成数据集，旗舰模型基于它出设计方案，反复迭代出一份自己的 UI skill。

## 二、和我写过的东西，几乎同构

读这篇的时候我一直在对照本博客的「Agent 开发手记」系列。两个互不相识的作者，收敛到了同一套结构：

| 热帖的做法 | 本博客的对应 | 共同的内核 |
| --- | --- | --- |
| 分歧清零再动工 | [先问答，再动工](/blog/agent-dev-1-requirements/) | 你就是需求评审 |
| 工程文件教接手的模型怎么查 | 需求是写给两个读者的 | 文档为上下文丢失的那天做准备 |
| 阶段验收门禁、方案对话只审查 | [验收标准先行](/blog/agent-dev-3-acceptance/) | 形容词换成可检验的陈述 |
| 换窗节奏、审查换窗口 | [漂移不是玄学，钉住它](/blog/agent-dev-2-drift/) | 长上下文是漂移的温床 |

这种趋同不是巧合。工具在变、模型在变，但「单人 + Agent 做中大型项目」要过的关卡就那几道：需求澄清、上下文持久化、过程监控、结果验收。谁都会在同一个地方撞墙，然后长出差不多的护栏。

## 三、两点热帖没说透

**文档会腐烂，而且比你想的快。** 评论区有一条被低估的质疑：这套文档体系像企业界的 arc42，当年正是因为「文档太重、与代码歧义太多」推行失败。热帖作者的对冲手段是每半个月让旗舰模型读一遍近期任务历史，集中清理过时内容——有效，但本质是人肉 GC，长期烧 token。我的做法是把一致性检查尽量交给机器：文档索引可校验、失效链接能报错、孤立文档有 doctor 检查（见 [DocPath 设计手记](/blog/docpath-1-why-fsm/)）。**文档不是资产，是缓存；是缓存就得有 GC，GC 能自动就别手动。**

**模型名是变量，分级是常量。** 热帖里的 Astra、6.1sol、DeepSeek 4.1 flash，三个月后多半换一批名字。但「最强模型做方案、性价比模型做执行、另一个窗口做审查」这个结构不会过时。抄帖子别抄模型名，抄结构。

## 写在最后

热帖值得收藏——但收藏之前，先把那个认知装进脑子：用 Agent 做中大型项目，瓶颈早已不在「会不会写 prompt」，而在有没有工程纪律。提示词会过时，纪律不会。
